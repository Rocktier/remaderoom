# 出图引擎接入指南（给店主/接手的人看）

这份文档只做一件事：把工作台从「演示用的示例图」变成「真出图」。
全程不需要懂代码，只需要会注册账号、复制粘贴、敲两行命令。

---

## 0. 结论先说：用的是火山方舟 · 豆包 Seedream

在「豆包 Seedream（火山方舟）」「通义万相（阿里云）」「智谱 CogView」里选的是**火山方舟**。理由：

| | 火山方舟 · Seedream | 通义万相 |
|---|---|---|
| 要几个凭据 | 1 个 API Key | API Key ＋ 业务空间 ID（WorkspaceId） |
| 返回方式 | 同步，一次请求直接回图（也支持直接回 base64） | 默认异步，要先建任务再轮询查结果 |
| 图生图 | 一个 `image` 参数搞定 | 字段结构更绕 |
| 国内访问 | 稳定 | 稳定 |

起步阶段少一个坑就少一分接不上手的概率，所以先接最简单的这家。
代码里引擎是单独一个函数（`server.mjs` 的 `callArk`），以后想换万相，照它的入参出参再写一个函数就行，前端一行都不用改。

**为什么不走浏览器直连：** 纯静态页面的 JS 是公开的，Key 写进 `js/` 里等于贴在门口。
所以由 `server.mjs` 这个本机小程序保管 Key，浏览器只跟本机它说话。

---

## 1. 准备（一次性）

需要 Node.js 18 或更高。命令行里敲：

```
node -v
```

显示 `v18.x` 以上就行。低于 18 去 nodejs.org 装个新的。

---

## 2. 拿到 API Key（约 5 分钟）

1. 打开 volcengine.com，注册并**实名认证**（不实名开不了模型）。
2. 控制台搜索「火山方舟」，进入。
3. 左侧「开通管理」/「模型列表」里找到 **Doubao-Seedream**（图像生成），点开通。
   有免费额度的话先领，不够再充值；先别大额充值，等验证过效果再说。
4. 左侧「API Key 管理」→ 新建 API Key → 复制那串密钥。
5. 回「模型列表」复制**模型名**，形如 `doubao-seedream-4-0-250828`。
   这个必须照抄，写错会报「模型不存在」，而且这个错在界面上也能看到。

> 各家控制台菜单改名很频繁。找不到入口就在控制台顶栏搜索框里搜 `Ark` 或 `Seedream`。

---

## 3. 填进配置

把 `engine.config.example.json` 复制一份，改名为 `engine.config.json`（同目录下），改成：

```json
{
  "provider": "ark",
  "maxRendersPerDay": 20,
  "ark": {
    "key": "这里粘贴你的 API Key",
    "model": "doubao-seedream-4-0-250828",
    "size": "2K",
    "watermark": false
  }
}
```

三个字段要注意：

- `provider` 从 `mock` 改成 `ark`，**这一步不改，永远还是示例图**。
- `model` 照抄控制台里的名字。
- `watermark: false` 关掉豆包的角标，否则效果图上会带 logo，客户看着像广告。

`engine.config.json` 已经被 `.gitignore` 排除，不会提交；同时本机服务也拒绝通过网页把它发出去（访问一律 403）。所以**别把它发到微信群、也别截图**。

---

## 4. 启动、自检、开用

```
node server.mjs
```

窗口会打印类似：

```
一键生成效果图 · 本机预览：http://localhost:5173
同一 WiFi 下的手机访问：http://192.168.1.2:5173
出图引擎：ark，每日上限 20 张
```

最后一行读到 `ark` 才算配置成功；读到「未配置」就按括号里那句人话去改。

浏览器打开 http://localhost:5173/workbench.html，上传一张真实的家里照片，选风格，点生成。
真出图通常 20 秒到 1 分钟。成功后结果上方会写「效果图已生成，用时 N 秒」——**没有这句示例图提示，就是真出图了**。

浏览器里也可以直接访问 http://localhost:5173/api/health 看状态，正常是：

```json
{ "ok": true, "provider": "ark", "configured": true, "note": "ready", "today": 0, "limit": 20 }
```

`configured: false` 时 `note` 里会直说缺什么。

## 5. 给客户演示时（手机）

手机和这台电脑连**同一个 WiFi**，用手机浏览器访问上面打印的那个 `http://192.168.x.x:5173` 即可，
现场拍一张照片直接出图。

两点安全提醒：

- 同一 WiFi 里的人都能访问这个地址、都能点生成，所以有 `maxRendersPerDay` 兜底。
- 演示完把这个命令行窗口关掉（Ctrl+C 或直接关窗口），服务就停了。

## 6. 出错对照表

界面上报错都是人话，不用看代码。对应处理：

| 界面上说 | 实际原因 | 怎么办 |
|---|---|---|
| ark.key 还是空的 | 没填 Key，或填的是示例占位文字 | 回第 3 步 |
| Key 不对或已过期 | 401 | 重新建一个 Key，注意别漏掉首尾字符 |
| 账号未开通该模型 | 403 | 去「模型列表」先点开通 |
| 请求太频繁或余额不足 | 429 | 等一会儿；或去充值 |
| 出图超过 150 秒没返回 | 超时 | 重试；这张不扣次数 |
| 连不上火山方舟 | 网络 | 检查这台电脑能不能上外网 |
| 连不上本机出图服务 | 那个命令行窗口被关了 | 重新 `node server.mjs` |
| 今天本机出图已到 N 张上限 | 触到 `maxRendersPerDay` | 调大那个数字，或等第二天（按**本地零点**自动重置） |

失败不扣前端免费次数，只有真出图成功才扣。

## 7. 还没做的部分（别被客户问住）

- **账号与支付**：免费次数存在浏览器 sessionStorage 里，换设备/清缓存就重置，只能算演示用。
  真正看住钱包的是服务端 `maxRendersPerDay`。微信/支付宝收款还没接。
- **出图历史**：生成结果只在当前页面里，关掉就没了。要发给客户得截图，或者以后把图存下来。
- **真实效果**：`callArk` 的接口结构是按官方文档写的，但**还没有用真 Key 跑通过一次**。
  第一次填 Key 后建议先用一张光线好、正对房间的远景照试，重点看墙、门、窗、层高有没有被改动——
  这套产品的信任点就是「还是你家」，指令里已经死死压住结构，但真图出来仍要肉眼确认一次。
