# 一键生成效果图 · 落地页设计文档

> 日期：2026-08-25 · 范围：本轮只做「落地页 + 占位工作台页」
> 面向：国内建材/卫浴个体户引流转化 · 视觉：温暖家装感

## 1. 目标与成功标准

- 目标：做出一张可直接展示给客户的**现代化、温暖、上档次**的落地页，用于引流（免费试用）和日后的付费变现铺垫。
- 成功标准：
  1. 本机 `index.html` 双击即可预览，移动端自适应。
  2. 落地页上的「免费试用」按钮可跳转到占位工作台页。
  3. 页面整体视觉温暖家装感，信息传达清楚：能出图、怎么用、免费试用。

## 2. 用户与转化路径

| 环节 | 描述 |
|---|---|
| 访客 | 有新房/旧房装修、卫浴厨房改造诉求的国内 C 端用户 |
| 触发 | 引导「免费试用 · 获取效果图」 |
| 去向 | 点击 → 占位工作台页（`workbench.html`，提示”工作台搭建中，即将上线“） |
| 后续 | 工作台完成后接真实出图；支付/会员后续阶段再加 |

## 3. 技术方案

- 选型：**纯静态多页**（HTML + CSS + 少量原生 JS），零依赖、零安装、浏览器直接打开。
- 文件结构：
  - `index.html` — 落地页
  - `workbench.html` — 出图工作台（三步：上传照片 → 选风格 → 生成并前后对比）
  - `css/style.css` — 共用样式（两页都可引）
  - `js/main.js` — 落地页交互：前后对比滑块、锚点导航、GSAP 动效
  - `js/config.js` — 站点参数：风格清单、免费次数、出图调用（走本机代理）
  - `js/workbench.js` — 工作台三步流程与滑块
  - `js/libs/` — 本地化的 GSAP 与 ScrollTrigger
  - `img/` — 本地效果图素材（12 张 JPEG，共约 0.8MB，无外链依赖）
  - `server.mjs` — 本机预览 + 出图代理（零依赖，Node 18+）；持 Key，静态页照常服务
  - `engine.config.example.json` — 配置模板；复制成 `engine.config.json` 填 Key（已 gitignore、HTTP 一律 403）
  - `docs/出图引擎接入指南.md` — 给店主的接入步骤与报错对照表
- 说明：落地页仍是纯静态，双击即可打开看；只有**真出图**需要 `node server.mjs`。
  `file://` 打开时没有代理，前端自动退回示例图并说明原因，不会白屏或报错。
  仍不引入构建工具与框架；日后接真实账号/支付时再迁移 Next.js，迁移路径见 §8。

## 4. 落地页结构（index.html）

1. **顶部导航**：站名「一键生成效果图」+ 锚点导航（效果展示 / 怎么用 / 适用场景 / 方案价格）+ 右上「免费试用」按钮。
2. **Hero 首屏**：大标题「上传照片 · 一分钟看到新家效果」+ 副标题 + 主 CTA「免费试用」→ `workbench.html` + 一张温暖改造前后对比大图。
3. **前后对比**：拖动滑块查看「改造前 / 改造后」（原生 JS 实现）。
4. **风格案例**：奶油风 / 原木风 / 宋式美学 三张案例卡（配套效果图）。
5. **三步怎么用**：① 上传效果图 ② 选风格（中古/宋式/奶油等）③ 自定义补充（可选）→ 一键出图。
6. **适用场景**：卫浴间 / 厨房 / 客厅 / 全屋。
7. **方案与免费试用**：免费试用卡片 + 「付费解锁更多风格 / 更多次数 / 高清」轻量说明。
8. **页脚**：一句话价值主张 + 联系方式（先留占位）。
9. 全程移动端优先。

## 5. 占位工作台页（workbench.html）

- 居中区块：图标 + 「工作台搭建中 · 即将上线」+ 一句说明（上线后可上传照片、选风格、写自定义描述，一键生成效果图）+「返回首页」按钮。
- 复用 `style.css` 保持视觉一致。

## 6. 视觉规范（温暖家装感）

- **底色**：奶油米 / 暖白为主，干净柔和。
- **主色**：木棕 / 暖咖色用于按钮与点缀；金色可作轻点缀。
- **字号层级**：H1 醒目（≥28px）、正文 15–16px、辅助 13px；行距宽裕、留白充足。
- **图片**：使用温暖色调的室内效果图（暖米、原木、奶油），真实、有生活感，避免冷色科技感。
- **组件**：圆角卡片、柔和阴影、前后对比滑块；无明显渐变滥用，保持干净高级。

## 7. 边界与非目标（YAGNI）

本轮**不**做：
- 真实出图引擎、账号系统、支付、会员
- 后端 / 数据库 / 构建工具
- 多页面管理、CMS

## 8. 后续迁移路径

- 当需要真实工作台（上传→选风格→出图）、登录与支付时，将本项目迁移到 Next.js 工程（App Router），保留现有结构语义与视觉规范，再把 `index.html` 各区块落地为组件、接入后端与 AI 出图 API、微信/支付宝。

## 10. 变更记录

### 2026-09-22 接手第一轮：素材本地化 + 两处布局/可访问性缺陷

1. **效果图全部换成本地文件**。原先 16 处引用 `trae-api-cn.mchost.guru/api/ide/v1/text_to_image`（上一轮在 Trae IDE 内的临时出图通道）已失效：不论 prompt 为何，一律 302 到同一张 `default.jpeg` 占位图，图上写着 "The image is generating, Please refresh page to preview."。现改为 `img/` 下 12 张本地 JPEG（15.4MB PNG 压成 0.8MB JPEG），`index.html` 15 处 + `js/config.js` 1 处外链引用清零，离线可看、不再受第三方接口时效影响。改造前后成对图片按「同一间房、同机位、墙体门窗布局不变」描述生成，与产品主打的信任点一致。
2. **修复首屏主图高度塌陷**。`.frame[data-ba]` 内两张图都是 `position:absolute`，容器没有自带比例，导致实测高度只有 2px（等于边框），首屏大图在页面上完全看不见。补 `aspect-ratio:4/3`。
3. **修复首屏大标题断行**。58px 时第二行差 8px 放不下「样子」，末行只剩两个字。标题降到 `clamp(34px,5.2vw,54px)` + `text-wrap:pretty`，并把 `hero-grid` 左栏由 1.02fr 加宽到 1.08fr（间距 56→48px），桌面端现为两行。
4. **工作台「下一步」由 `<a>` 改为 `<button>`**。原来是无 href 的 `<a>`：不进键盘焦点顺序、无障碍树里读不出来、也没法作为按钮操作。
5. **触屏隐藏 hover 提示**。落地页 Hero 与案例卡靠 `:hover` 露出「改造前」，手机没有 hover，提示语会变成误导。加 `@media (hover:none)` 隐藏「悬停看改造前」「悬停 · 改造前」标记。

### 2026-09-23 接手第二轮：出图引擎接上本机代理，工作台从假出图变可真出图

1. **新增 `server.mjs`（零依赖，Node 18+）**：静态预览 + `POST /api/generate` + `GET /api/health`。
   Key 只留在本机 `engine.config.json`，不进任何浏览器可见文件。选型定为**火山方舟 · 豆包 Seedream**
   （只要一个 Key、同步返回、支持 base64 入参）；阿里万相需 WorkspaceId 且默认异步轮询，留作以后换引擎。
2. **出图指令把住房间结构**：prompt 里硬性要求机位、透视、层高、墙体/门/窗/梁位置尺寸完全不变，
   只允许换饰面、天花、灯具、家具、布艺与摆件——这是本产品「图好看 × 还是你家」的信任点。
3. **`js/config.js` 改异步**：`generateImage()` 返回 Promise，成功 `{ok,demo,afterUrl,seconds}`、
   失败 `{ok:false,code,message}`，`message` 一律是人话。上传前用 canvas 把手机原图压到长边 1400px
   （实测一张 1024px 照片 → 请求体 141KB）。`App.ENGINE` 字段取消。
4. **失败不再用 `alert()`**：新增第 3 步内的错误块 +「回上一步重试」，且**失败不扣免费次数**。
5. **每日出图上限兜底**（服务端 `.renders.json`，默认 20/天）：同一 WiFi 里别人也能访问本机服务，
   靠它守住钱包。
6. 修了 4 个这轮改动自身带出来的缺陷：
   - **第 3 步面板卡住**：`initSlider()` 收到 `.ba-slider` 自身后又在它内部找 `.ba-slider`，拿到 `null` 抛异常。
     异常发生在「扣次数」之后、`go(3)` 之前，表现为次数已扣但页面什么都没有；控制台只有一条未处理 Promise
     拒绝，界面上毫无线索。现让该函数两种入参都接受，并把整条 `.then()` 链补上 `.catch()` 兜底显示。
   - **每日上限按 UTC 翻页**：`toISOString()` 会让北京时间到早上 8 点才重置，与提示语「明天自动恢复」不符。
     改为按本地日期取 key。
   - **`/api/health` 未配置时报 `provider:"none"`**，把已填的 `ark` 盖掉了；现在错误分支也带回真实 provider，
     并补 `configured` 与 `limit` 字段。
   - **示例图文案过期**：mock 模式下仍写「出图引擎尚未接入」，实际代理已通、只是 `provider` 还留在 mock。
     改由服务端给出准确说明。
7. 安全边界实测：`engine.config.json`、`server.log`、以 `.` 开头的文件（含 `.renders.json`）经 HTTP 一律 403，
   `%2e%2e%2f` 与 `--path-as-is` 两种路径穿越写法同样 403。
8. 端到端实测（`provider:"mock"`，Chromium + 本机代理）：真实拖拽上传 → 5 张风格卡 → 生成 →
   `p3` 可见、结果图 1000×750 以 base64 到手、次数 3→2、滑块分隔线随拖拽落到 88.9% 且 `clip-path` 同步。
   错误路径同样跑通：未填 Key → 503 提示去建 Key；触顶 → 429 提示次日恢复；空请求 → 400「没收到照片」。

### 已知遗留

- **`callArk` 尚未用真 Key 跑通过一次**：接口结构与错误码分支都按官方文档实现，但真图效果、
  以及该模型是否接受 `image: [dataURL]` 与 `size:"2K"` 这组入参，仍待第一次真实调用确认。
- 免费次数只是前端演示：存 `sessionStorage`，换设备或清缓存即重置；mock 模式下结果图与所选风格无关。
  账号体系与微信/支付宝支付均未接，真正守钱包的只有服务端 `maxRendersPerDay`。
- 生成结果不留痕，关掉页面即丢，没有出图历史可发给客户。
- 页面没有 favicon；`img/` 素材未做 WebP 双份。
- 案例卡的「改造前」复用了首屏与对比区的图（`hero-before`、`ba-before`），同一张旧房图出现在两处，后续可按案例各自补一张。
